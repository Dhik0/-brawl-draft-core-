## analyze 阶段克制算法重构（Log5 残差 + 贝叶斯平滑）

**动机**：旧的克制分直接用「A 打 B 的原始胜率」对比 50%，把「英雄本身强度」和
「对位关系」混在一起——强势英雄对谁都能赢，就被判成克制所有人。

**实现**（`src/analyzer.rs` 全量重写）：
- `log5(p_a, p_b)`：预期对位胜率，基础胜率截断 `[0.05, 0.95]`。
- `residual_delta(w, n, E, C)`：`(w - n*E)/(n + C) * 100`，单位 pp，C 默认 15。
- 反对称性**由构造保证**：只按 `(min_id, max_id)` 算一次再镜像写入，不靠浮点巧合。
- 层级兜底：地图层用「留一图」的模式残差做先验，权重 `C * max(0, 1 - n/15)`
  连续收缩到 0（`n>=15` 完全信任单图，与纯单图公式连续衔接）。
- 克制层用**原始计数**（可手算复核），胜率榜仍用时间衰减加权值。

**导出结构**（schema v3）：
- `Matchup { opponent, delta, samples }`，delta 保留 2 位小数。
- `MapBrawlerStat` 新增 `matchups`（前 8 优势 + 前 8 劣势，按 delta 降序）。
- `ModeBrawlerStat.matchups` 改为按 |delta| 取 Top 12。
- 新增 `tier_audit`（段位分布 + 过滤前后对局数）。
- 体积 3.25MB → 2.31MB。

**关键数据发现**：`brawl.db` 里 `battles.avg_tier` **全部为 0**（143,975 局），
`players.tier` 也全为 0。官方 battlelog 不返回 rank，`average_rank()` 恒为 `None`
→ 入库写 0。因此**段位门槛在当前库上无法生效**，MIN_TIER 一直是空转。
过滤逻辑已实现（`avg_tier <= 0` 视为未知并保留，由 `TierAudit` 单独报告），
但要真正按段位统计，需要新数据源或落库奖杯数做代理——存量数据无法回溯。

**验收**：单图平均 5538 局（26 图，最少 75）。Sneaky Fields 6038 局，
SPIKE 1630 局 wr=0.5155。地图级与模式级共 25,884 组双向对位，反对称校验 0 失败；
SPIKE vs EL PRIMO 的 delta=-9.41 与从原始 DB 独立复算完全一致。

## 段位解析修复 + 纯高段位库重建（方案 ②）

**字段事实（用户纠正，已实测确认）**：排位 battlelog 的 `brawler.trophies` 不是奖杯数，
而是官方下发的**排位段位整数 1~22**（1-3 青铜 / 4-6 白银 / 7-9 黄金 / 10-12 钻石 /
13-15 神话 / 16-18 传奇 / 19-21 大师 / 22 职业）。实测 `#20L88L2J` 的 soloRanked
对局里 6 名玩家 trophies 全是 18/19，即传奇 III / 大师 I。
之前 `average_rank()` 取 `brawler.rank`（API 从不返回）→ 全库 avg_tier=0，MIN_TIER 空转。

**改动**：
- `api.rs`：新增 `ranked_tier_of()`（trophies 优先，回退 rank，均校验 1..=22）、
  `player_tiers()`、`average_tier()`（四舍五入，避免 15.5 被截断成 15 跨不过门槛）。
- `db.rs`：`IngestFilter` 增加 `min_enqueue_tier`；`set_player_tier` 改为**只 UPDATE 已入队玩家**
  （原来 INSERT 会让所有被解析出段位的玩家绕过入队门槛）；`next_crawl_batch` 改为
  `ORDER BY tier DESC, last_crawled_at ASC`。
- `crawler.rs`：battlelog 倒序处理，保证最后写入的 players.tier 来自最新对局。
- `config.rs`：`MIN_TIER` 默认 16（传奇 I），新增 `ENQUEUE_MIN_TIER` 默认 15（神话 III）。
- `output.rs`：`TierBucket` 增加 `label`；新增 `tier_label` / `tier_group`。
  `filter_effective()` 语义修正——门槛在入库阶段生效，analyze 阶段无过滤是正常现象。

**迁移与实测**：`brawl.db` → `brawl_legacy_notier.db`（备份保留），新建空库，
`crawl --seed --seed-limit 200 --limit 50` 后再补抓两轮，共 69 名玩家。

**结果**：364 局全部 >= 16，段位未知 0。分布 大师 240 (65.9%) / 传奇 124 (34.1%)，
明细 大师 III=3、大师 II=83、大师 I=154、传奇 III=55、传奇 II=40、传奇 I=29。

**关键发现**：种子源是**奖杯**全球榜，这批玩家的对局绝大多数是 `not_ranked`（奖杯赛），
首轮 50 人 1066 局被过滤、只入库 105 局；雪球出来的高段位玩家命中率高得多
（8 人：入库 59 / 过滤 71）。后续扩量应少用奖杯榜种子、多靠雪球。
单图平均只有 15 局，距 500 局目标还差约 35 倍（约需 1.3 万局 / 2000+ 玩家）。

## 评分公式与顺位判定重构（Shooting Star 失真修复）

**问题**（对照高段位实战）：`score = 0.75*平滑胜率 + 0.25*归一化出场率` 让热门卡
线性碾压强卡（PIPER 52.8%胜率/9.8%槽位 = 100 分，MR. P 56.9%/3.1% = 52.9 分）；
冷门卡靠贝叶斯平滑停在 50% 胜率白嫖分数；顺位里无对位样本的近战克制方差为 0，
被误标 FIRST（JACKY 2 场 100% 胜率 → FIRST）。

**新评分**（`src/analyzer.rs`）：
```
rel      = games/(games+40)                    // 可靠性
wr_core  = 0.5 + (p_smoothed-0.5)*rel          // 薄样本拉回中性
use_term = ln(1+share*300)/ln(1+max_share*300) // 对数压缩，0~1
raw      = 0.92*wr_core + 0.08*use_term
```
`share = use_rate/6`（导出字段 use_rate 是每场出场数，合计≈6）。
Min-Max 分母只算「有效英雄」（games>=10 且 share>=0.5%），否则冷门卡会把区间压扁。
极冷门（games<10 或 share<0.3%）综合分封顶 35。

**新顺位**：只有 games>=20 && share>=0.5% && 有效对位边>=3 的英雄参与
FIRST/LAST 分位划分，其余一律 MIDDLE。配额按**合格英雄数**算。
新增 `analyzer::is_ranked_pick_candidate()` 供 CLI/前端/测试共用同一门槛。

**验收**（47,112 局，Shooting Star 2,005 局）：MR. P 100 / PIPER 98.99 / VINCE 94.05 /
MELODIE 93.22 / NAJIA 90.22，顶部平滑无断崖；ROSA(#79, 9.83)、JACKY(#67, 11.20) 均为 MIDDLE。
顺位分布（合格 910 名）FIRST 21.6% / MIDDLE 56.7% / LAST 21.6%。
全库校验：不合格却标 FIRST/LAST = 0，冷门分>35 = 0。

**注意**：FIRST 由 `flex`（模式级胜率 − 被康特惩罚）决定，与 score 是两个轴。
所以 ANGELO(74.7) 是 FIRST 而 MELODIE(93.2) 是 MIDDLE——后者被 EL PRIMO -13.55pp 硬克。
若要让顺位改用地图层克制，是后续可选项。

## 顺位判定改用地图层克制（去掉模式级污染）

**改动**：`build_map` 不再接收模式级 `profiles`，改为用**本图**的 `pairs` + `delta`
现场提取对位画像（`extract_profiles(&pairs, &delta, min_export)`）：
- `flex = 平滑胜率 − 0.30 × penalty`，penalty 取本图最差 delta；
- `spread_pp`（判 LAST 用）也来自本图。
`ModeContext` 删掉 `delta` 字段（只剩 base + pairs 做「留一图」先验），
`analyze` 里那段按模式预计算 profiles 的代码整体移除。

**效果**（Shooting Star）：模式级最差对位是 EL PRIMO / ASH / 8-BIT / MICO 这类近战，
在开阔狙击图上属于无关地形的污染；地图级变成 MR. P←MAX -15.74、MELODIE←PEARL -15.11、
ANGELO←R-T -8.50。顺位因此变动 6 个：MR. P FIRST→MIDDLE、NAJIA MIDDLE→FIRST、
NANI FIRST→MIDDLE、AMBER LAST→FIRST、MAX MIDDLE→LAST、MINA LAST→MIDDLE。
全局分布不变（FIRST 21.6% / MIDDLE 56.7% / LAST 21.6%，配额本来就按合格英雄数算）。

**新增回归测试** `pick_order_uses_map_level_counters_not_mode_level`：
同模式两张图，1 号在 M1 被完克、在 M2 全胜无劣势对位，断言 M2 上仍判 FIRST
（旧模式级实现会因 M1 的惨败把它压掉，测试会失败）。
