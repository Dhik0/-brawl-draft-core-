## brawl-draft-core 从零构建完成（阶段 1~5 全绿）

- 工程：Rust 2021，依赖严格按用户白名单（tokio/reqwest+rustls/serde/rusqlite bundled/rayon/clap/anyhow/tracing/sha2/hex/dotenvy/chrono）。
- 结构：`src/{main,lib,config,db,crawler,analyzer,publisher}.rs`、`src/models/{api,output}.rs`、`src/db/mock.rs`、`tests/pipeline_tests.rs`、`config/brawler_roles.json`、`.env.example`。
- 与规范的两处偏差（有意为之）：
  1. 增加 `src/lib.rs`——`tests/pipeline_tests.rs` 必须能导入内部逻辑，二进制 crate 做不到。
  2. mock 生成器放在 `src/db/mock.rs`（`db` 的子模块），未新增顶层文件。
  3. 增加辅助表 `brawlers(id, name)`——`battles` 只存整数英雄 ID，导出时需要它还原名字。
- 关键设计决定：
  - `battle_hash = SHA256(battle_time | 字典序排序后的 6 个 tag)`，与顺序无关。
  - 胜负判定依赖 **battlelog 所属玩家**（`observer_tag`）+ `battle.result`，不能只看 teams 顺序。
  - 排位赛 `event.mode` 是 `soloRanked`，真实玩法在 `battle.mode`；`mode` 字段取后者。
  - `battleTime` 末尾 `Z` 是字面量，必须用 `NaiveDateTime::parse_from_str` 再 `.and_utc()`（`DateTime::parse_from_str` 会因缺时区失败）。
  - `config/brawler_roles.json` 只写英雄名，不写 ID；analyze 阶段按 brawlers 字典解析成 `brawler_ids`，避免手写 ID 漂移。
  - score = 0.75*平滑胜率 + 0.25*归一化出场率，再按地图 Min-Max 到 100；单英雄地图给中性 50。
- 验证：`cargo test` 43 passed（38 lib + 5 integration），`cargo clippy --all-targets -- -D warnings` 零告警，生产路径无 unwrap/expect。
- 端到端：`mock --count 5000` -> `analyze` 产出 `dist/brawl_meta.json` 89.6 KB / 6 图 / 63 英雄；`push` 在临时 git 仓库验证过「无变更跳过 / 有变更提交推送」。

## 改造：默认走 RoyaleAPI 中转代理（绕开 403 Invalid IP）

- 配置项改名 `BRAWL_API_BASE` -> `BRAWL_API_BASE_URL`，字段 `Config::api_base` -> `api_base_url`。
- 默认值改为 `https://bsproxy.royaleapi.dev/v1`（`DEFAULT_API_BASE_URL`）；官方直连地址保留为常量 `OFFICIAL_API_BASE_URL` 仅作注释/测试用。
- `resolve_api_base_url()`：空值回退默认 + 统一 `trim_end_matches('/')`；`crawler::join_url()` 再兜一层，两侧斜杠归一化，杜绝 `//players`。
- `PROXY_URL` 逻辑、Bearer 头、限流与退避全部未动（中转域名在国内仍需本地代理节点）。
- 403 提示语改为「Key 无效 / 出口 IP 不在白名单 / 可改回默认中转代理」。
- 实测：假 Key 请求 `bsproxy.royaleapi.dev` 返回 403，证明 URL 拼接与默认值生效。
- 验证：48 tests passed（43 lib + 5 integration），clippy `-D warnings` 零告警。

## 改造：数据建模优化（模式级克制矩阵 + 时间衰减 + 分位顺位）

- **输出契约升到 schema_version 2**：新增顶层 `modes[]`，`maps[].brawlers[]` 不再带 `matchups`，`Matchup` 新增 `smoothed_wr`。前端按 `map.mode` 去 `modes[]` 查矩阵。
- 克制矩阵改为 `(mode, a, b)` 聚合，阈值 15 -> 6，对位也做贝叶斯平滑（m=6，先验 0.5）。
- 时间衰减：`w = 0.5^(Δt/30)`，基准是**数据集内最新对局**而非 now（保证离线重算可复现）。`games/wins` 输出原始计数，`win_rate/smoothed_wr/use_rate` 是加权比率——两者刻意不相等，已在结构体文档写明。
- 顺位改为**分位分配**（`assign_pick_orders`）：先取 spread 最大的 22% 为 LAST（需 spread>=0.08 且至少 2 条对位），再从剩余取 flex 最高的 22% 为 FIRST。flex = 平滑胜率 - 0.3*max(0, 0.48-worst)。
- `SEASON_START_DATE` -> 2026-07-20（.env 与 .env.example 同步）。
- 真实数据实测（5746 场 / 24 图 / 6 模式 / 108 英雄）：克制覆盖率 13.7% -> **63.4%**，平均对位数 0.40 -> **7.94**，平滑后胜率范围 0.167~0.833（无 0%/100%），顺位 **22.2% / 55.7% / 22.2%**，导出 685 KB。
- 注意：当前数据跨度仅 2 天，时间衰减权重实际全为 1.0，该逻辑要等库里有跨月数据才生效（单测已覆盖）。
- 验证：53 tests passed（48 lib + 5 integration），clippy 零告警。
